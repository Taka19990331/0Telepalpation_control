# chirp_multi-cycle：15サイクルチャープ

## 実行順序

`s`を入力すると記録準備と既存のモータ起動待ちを行い、フィードバックが有効になった後、次のB–Dを15回繰り返す。

| 区間 | 動作 | 時間 | データ記録 |
|---|---|---:|---|
| A | 起動・有効フィードバック待ち | 最大0.5秒（待ち時間） | なし |
| B | トルク要求0 Nm、PD無効。受信位置の平均を基準位置にする | 1秒 | あり |
| C | 現行の平均位置基準PD＋対数チャープ | 20秒 | あり |
| D | チャープなし、平均位置基準PDのみ | 2秒 | **なし** |
| F | 既存の停止処理 | 数ミリ秒程度 | 停止行のみ異常終了時に記録 |

B–Dの1サイクルは23秒、15サイクルで約345秒（5分45秒）。起動待ちと停止処理はこの時間に含まない。サンプリングは2000 Hz。Cのチャープ式・周波数1→100 Hz・振幅設定・PDゲイン・トルク上限は元プログラムと同じ。

各B区間で新しく受信した有効位置だけを平均し、そのサイクルのCとDでPD目標位置に使う。Dは制御周期とモータ指令を継続するが、Sample行をリングバッファへ追加しない。したがって記録の`actual_us`と`nominal_us`はD区間で約2秒飛ぶ。ログの行番号ではなく、`index`が全制御周期上の位置を表す。

## 現行設定

設定は`chirp_config.h`。元スケッチから継承した値は、`MOTOR_SELECT=80B`、CAN2/ID2、チャープ振幅1.5→10 Nm、実験トルク上限±15 Nm、P=0.00834 Nm/deg、D=0.1 Nm/(rad/s)。合計指令が上限を超えると停止する。

通常はB+Cの42,000行×15サイクルと停止行予約・平均区間の余裕を含め、最大630,061行を予約する。通常完了時の行数は630,000行。SD形式は元のSI1と区別する`CHIRPMC1 / ENDMC001`、ファイル名は`MC0000.BIN`等。

シリアル操作は`s`開始、`x`中止、`d`最新ログ取得、`p`そのひとつ前のログ取得。`p`による取得はこの版のファームウェアが必要。

```powershell
powershell -ExecutionPolicy Bypass -File .\sys_identification\chirp_multi-cycle\capture_multi_cycle_com.ps1 -Port COM3 -Which latest
```

`-Which previous`でひとつ前のログを取得できる。USBシリアルから取得したCSVと生シリアルログ、検証JSONは`captures`に保存される。受信バッファを拡大し、ファイル書き込みはまとめて行う。行数、時刻、完了状態を確認し、転送や検証に問題があれば失敗として記録する。

すでに記録済みのカードから取り出す場合は、ファームウェアを書き換えずに、SDカードリーダーで`MC0000.BIN`と`MC0001.BIN`をPCへコピーし、次でCSVに変換できる。

```powershell
.\sys_identification\chirp_multi-cycle\convert_multi_cycle.ps1 'D:\実際の保存場所\'
```

フォルダを渡すと、その中の`MC*.BIN`から更新日時が新しい2ファイルを選んで変換する。ファイルを指定する場合はBINのフルパスを直接渡せる。

Python版`convert_multi_cycle.py`も利用できる。CSVと設定・検証JSONはBINと同じフォルダに作成される。既存のSI1変換器ではMC1を変換できない。

元の`chirp_simplified_test1`のファイルは変更していない。
