# AK80-8 friction data analysis

Run `main.m` in MATLAB. It reads the configured FRIC001 CSV, searches each commanded torque step from the end for a stable interval, writes accepted and rejected step tables, then displays and saves the two standard figures. Configure input/output paths, thresholds, optional diagnostic plots, and motion labels in `config.m`.

## FR0007 observations

The CSV header is preceded by FRIC001 metadata. The recorded configuration reports AK80 selection (`IS_60=0`, `IS_80A=0`, CAN2 / motor ID 2), 1 MHz CAN, a 500 us control period, 0.02 Nm torque increments, +/-1 Nm configured torque range, 20 rad/s speed limit, 20 ms feedback timeout, 100 ms minimum settling, 2 s maximum settling, a 200 ms firmware detection window, 0.3 rad/s^2 acceleration and 0.08 rad/s speed deviation limits, and a 500 ms acquiring interval. The result footer reports 102623 rows and overall reason 4 (OVERSPEED), matching the 102623 data records.

The CSV actually contains Phase 1 and Phase 3 only. Phase 1 commands 0 to +0.62 Nm in 0.02 Nm increments and begins a +0.64 Nm step, which terminates with OVERSPEED; Phase 3 then starts at 0 Nm and decreases to -0.54 Nm, where it also terminates OVERSPEED. Phases 2 and 4 are absent. Each ordinary step spans about 0.781 s. Recorded control sampling is 500 us; the median unique feedback receive interval is 500 us and the largest observed interval is 1.159 ms. One repeated feedback sequence and one startup row with the invalid-age sentinel occur; no motor errors or missing finite speed/torque values occur during the active sweeps. Firmware states are 0 STARTUP, 1 SETTLING, 2 ACQUIRING, 3 STATIONARY, 4 COASTING, 5 BRAKING (unused), 6 EXITING, 7 FINISHED. Reason codes and event bits are parsed from metadata; event value 1 marks step start and value 2 marks step end.

The firmware logs the most recent feedback snapshot before sending the command recorded on that row. The step-start row therefore carries feedback from before the new target is sent and is excluded. A normal step-end row is emitted while the old target is still commanded and state is SETTLING/ACQUIRING/STATIONARY, so it can be included if its target matches that step. At an OVERSPEED end event the firmware has already changed target to zero and entered COASTING; that end row is excluded. The analyzer also truncates at the first changed target and never carries data across phase/step keys.

An independent data calculation using the default offline thresholds finds 61 phase/step groups: 58 accepted (Phase 1: 31; Phase 3: 27), and 3 rejected. The rejected groups are Phase 1 step 31 (+0.62 Nm, firmware UNSTABLE, only about 306 ms before termination), Phase 1 step 32 (+0.64 Nm, OVERSPEED), and Phase 3 step 59 (-0.54 Nm, OVERSPEED). No NOT_SETTLED stage occurs in this file, so none is newly recovered. All 58 accepted windows classify as STATIONARY: their absolute mean speeds are about 0.0054 to 0.0137 rad/s, and their measured position ranges are below 0.0008 rad. Their speed standard deviations are about 0.059 to 0.071 rad/s. This run therefore contains rest points but no clearly moving friction points; it cannot supply dynamic friction identification data.

## Offline rules

The default search considers 500 ms windows down to 400 ms, stepping both duration and end time by 25 ms. It compares requested duration with receive-time coverage and uses a 1 ms duration tolerance plus a 1.5-period (0.75 ms) sample-edge tolerance, avoiding false rejection from timestamp phase while still flagging invalid edge samples. Feedback checks include finite values, freshness, motor error, valid sequence, `feedback_rx_us` edge coverage and update gaps (2 ms maximum), invalid-sample fraction (2%) and invalid streak (5 ms maximum). Feedback is deduplicated by both sequence and receive timestamp before calculating means, standard deviations, and acceleration against receive time.

The general acceleration and speed-standard-deviation limits remain 0.3 rad/s² and 0.08 rad/s. The latter is about four configured speed counts and is too permissive by itself for deciding whether near-zero data are moving. For low-speed MOVING or UNCERTAIN windows, a tighter 0.04 rad/s standard-deviation limit applies, and position slope must agree with mean feedback speed. Strong position evidence of rest allows a window to remain a stationary point, but never makes it dynamic-friction-eligible. Stick-slip is only flagged when repeated position bursts are separated by plateaus and feedback direction corroborates; an instantaneous zero speed sample alone is insufficient. Position is unwrapped only for a jump over half the configured span when both samples are within 5% of opposite configured edges; the raw FR0007 stream contains two such confirmed wraps.

The steady CSV separates `Accepted` from `DynamicFrictionUsable`; only accepted MOVING windows with continuous position change and consistent feedback are eligible for dynamic friction identification. STATIONARY and UNCERTAIN windows may remain as steady observations, but have `DynamicFrictionUsable=false` with an explanation. The diagnostics CSV includes per-step candidate counts and separate counts for edge coverage, receive gaps, invalid clusters, acceleration, general and low-speed dispersion, and motion-consistency failures. In the comparison Fig. 2, phase is encoded by color and the threshold criterion by marker shape; MOVING points are shown by default.

`steady_state_data.csv` contains only accepted points. `steady_state_diagnostics.csv` contains each discovered phase/step, including firmware termination and offline rejection reason. The x-axis is mean measured speed; the y-axis is mean feedback estimated torque. Command torque is kept separate and appears only in diagnostics/time plots. No friction model fitting is performed.

## Three-level steady-window comparison

`main.m` now runs the existing window search independently against the same samples for `Strict`, `Relaxed 1`, and `Relaxed 2`. Strict keeps the configured acceleration and speed-deviation limits (0.3 rad/s^2 and 0.08 rad/s by default); the other limits are multiplied by `cfg.steady.relaxed_multipliers` (default `[2 4]`). Window durations, feedback validity, timing/coverage, phase and step grouping, motor-error checks, motion checks, and all other checks remain unchanged. Each run still accepts at most one window per phase/step. No RFOB, inertia compensation, or friction fitting is performed.

The original `steady_state_data.csv` and `steady_state_diagnostics.csv` remain the Strict outputs. `steady_state_comparison.csv` contains accepted points from all criteria with each criterion's selected window and measured metrics. `steady_state_comparison_diagnostics.csv` contains every phase/step diagnostic from all three independent runs. `steady_state_comparison_summary.csv` contains accepted/MOVING/STATIONARY/UNCERTAIN counts, moving direction counts, maximum absolute MOVING speed, thresholds, and new steps relative to Strict. The two standard figures remain `raw_velocity_torque.png` and `steady_velocity_torque.png`. Fig. 2 uses phase color and threshold marker shape (Strict circle, Relaxed 1 triangle, Relaxed 2 square); `cfg.plot.show_moving_only` defaults to true. Set it false to include non-MOVING points. `cfg.plot.show_zero_torque` controls both standard figures only; zero-command rows remain in source and CSV diagnostics. `cfg.plot.steady_threshold_distributions` opts in to the acceleration and speed-deviation distribution figure and defaults to false.

Each run also reports source sample count, unique step count, command-torque range, and speed range for Phases 1–4. A missing phase is reported as absent from the source file; the analyzer never synthesizes phase data.
