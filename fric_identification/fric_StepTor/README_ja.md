# StepTor トルクステップ実験

Teensy 4.1 / AK80 Motor ID 1（CAN1）またはID 2（CAN2）用。ID 3は異なるCANプロトコルのため未対応です。ConstVelと同じSDバイナリ記録→USBシリアルCSV抽出方式です。

## 設定と動作

`steptor_config.h`冒頭でサンプリング周波数、片方向のステップ数、トルク刻み、各ステップ保持時間、正負間のゼロ保持時間を変更します。初期設定は500 Hz（2000 µs周期）、合計32秒、通常16000サンプルです。SD事前確保行数は設定から自動計算します。

| 経過時間 [s] | 指令 [Nm] | stage |
|---|---|---|
| 0–5 | +1 | 0 |
| 5–10 | +2 | 1 |
| 10–15 | +3 | 2 |
| 15–17 | 0 | 3 |
| 17–22 | -1 | 4 |
| 22–27 | -2 | 5 |
| 27–32 | -3 | 6 |

位置・速度ゲインは両方ゼロ、速度指令値もゼロで、フィードフォワードトルクだけを指令します。速度超過停止、速度積分制御、積分トルク制限はありません。MIT通信の数値表現範囲（トルク±32 Nm、速度±37.5 rad/s等）は元スケッチと同じです。トルク範囲を超える設定では開始しません。モータ側の内部制限は本スケッチから変更しません。

通常終了ではサンプル生成を止め、残りのデータ・フッタをSDへ書き込み、sync/closeした後にゼロトルク指令とMIT終了指令を送って制御タイマを停止します。このため、最後の-3 NmはSD確定処理中も保持されます。終了後はCSV転送だけを受け付け、再実験にはTeensyのリセットが必要です。

通信タイムアウト、モータエラー、バッファ異常、送信失敗、SD書込失敗や手動中止時は異常終了します。通信異常や手動中止では即時ゼロ指令・MIT終了指令を送り、SD確定後にも送ります。終了コードは元と同じで0=正常、1=手動中止、2=バッファ溢れ、3=受信タイムアウト、4=モータエラー、6=送信失敗、7=SD書込失敗、8=SD確定失敗です（確定失敗時はCSVが取得できない場合があります）。

## 実行・抽出

Arduino IDEでTeensy 4.1を選び、`fric_StepTor.ino`を書き込みます。SDカードとCAN接続を用意してください。`s`で実験開始、`x`で中止、`d`で最新の確定ログをCSV転送します。サンプリング開始はフィードバック受信確認後です。

PowerShellで開始から抽出まで行う例（COM番号を変更）：

```powershell
cd C:\0Telepalpation_control\fric_identification\fric_StepTor
.\download_steptor.ps1 -Port COM5 -Start -DurationSeconds 32
```

実験済みの最新ログだけを取得する場合：

```powershell
.\download_steptor.ps1 -Port COM5
```

設定変更時は`-DurationSeconds`も合計実験時間（端数は切り上げ）に合わせます。スクリプトはさらに5秒待って転送要求します。シリアルモニタは閉じて実行してください。

SD名は`ST0000.BIN`以降、PC名は`data\StepTor_yyyyMMdd_HHmmss.csv`で、既存ConstVelとは区別します。同名CSVには連番を付けます。転送開始・終了マーカーと行数を検証して保存します。

CSV先頭の`#key,value`には周期、ゲイン、トルク刻み、ステップ数、保持時間、終了コードを出力します。データ列は時刻、指令トルク、位置、実速度、ドライバ推定トルク、フィードフォワードトルク指令、stage、エラー、受信有効フラグです。`command_torque_nm`と`feedforward_torque_command_nm`は同値です。推定トルクは独立したトルクセンサ値ではありません。
