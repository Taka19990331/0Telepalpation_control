# AK80_timer_test：500 Hz → 1 kHz → 2 kHz → 3 kHz シーケンス

## 操作
- Teensy 4.x / FlexCAN_T4 / IntervalTimer用。元のak80_low_torqueは変更していない。
- 初期設定：80B、CAN2、ID 2、1 Mbps、1 N·m、各段階1秒。Serial 115200。
- sでシーケンス全体を開始、xで全体停止（改行不要）。起動だけでは運転しない。
- 500 Hz（2000 µs）→ 1 kHz（1000 µs）→ 2 kHz（500 µs）→ 3 kHz（約333.333 µs）を各1秒、計約4秒連続運転する。
  段階間でトルクを解除せず、タイマー周期を変更する。結果のSerial出力は全段階終了後。
  100 Hzの段階は含まない。
- 起動・出力のバージョン表記はAK80_TIMER_SEQUENCE_V3。
- MOTOR_SELECT：80A（CAN1/ID1）、80B（CAN2/ID2）、60（CAN3/ID3）。
- STAGE_HZ={500,1000,2000,3000}、RUN_MS=1000（各段階）。空のloop()はArduinoリンク用のみ。
- 応答途絶100 ms、速度絶対値40 rad/s以上、モータエラーの停止条件を維持。各段階1秒後に次へ進み、最後はSEQUENCE_COMPLETEで停止。
- 次周期までに未応答ならRESPONSE_DEADLINE、送信受付失敗ならTX_FAILEDでシーケンス全体を停止し、それまでの結果を出力する。
- AK80停止はゼロ指令とMIT無効化。AK60停止はゼロ指令で、停止中も最後に設定された周期でゼロ指令を送る。

## 測定
1. タイマーISRでCan0.write()を呼ぶ直前にmicros()を記録。
2. CAN受信割り込みから直接呼ばれるreceiveISR()の先頭でmicros()を記録。
3. 対象モータの最初の有効応答を、未応答指令1件と対応づけてRAMに保存。
4. 停止後に全記録と集計をSerial出力。試験中の従来の20 Hz DATA出力は無効化。

各段階の最初の30 msをウォームアップとして記録対象から外す。各段階の1秒にこの30 msを含む。
周波数切替直後の過渡周期も測定対象外になる。3 kHzは浮動小数点の約333.333 µsをIntervalTimerに指定し、整数333 µsへの切り捨てを避ける。micros()の1 µs分解能によりPeriod_usは333または334になり得る。想定記録数は約485／970／1940／2910件（計6305件）。
未応答指令がないことを確認してから次段階へ切り替える。
Can0.events()を呼ばない。使用中のFlexCAN_T4ではevents未使用時にコールバックが受信割り込み内で実行される。
受信内容は64枠のキュー（有効63件）に入れ、タイマーISRで1周期最大32件を解釈する。
停止判定は各段階の制御周期で行うが、応答時刻は次周期を待たずに記録する。

CANとタイマーの割り込み優先度はともに192。互いに割り込ませず、ドライバとRAMの更新を直列化する。
測定には実行中の制御ISRや他の割り込みによる遅延も含む。1 µs単位のソフトウェア時刻であり、物理到着時刻そのものではない。

記録上限8192周期（28バイト×8192＝224 KiB）。4段階すべてをRAMに保持する。
上限ではTIMING_BUFFER_FULL、受信キュー溢れ・ハードウェア受信オーバーランではRX_OVERFLOWで停止する。
出力中は新しい試験を開始しない。RAMを上書きしない。

## 出力
TIMING_BEGINからTIMING_ENDまでを保存する。

TIMING,Hz,Index,Tick,TxRequest_us,RxCallback_us,RTT_us,Period_us,ISR_us,Status

| 列 | 意味 |
| --- | --- |
| Hz | 測定段階の指令周波数 |
| Index / Tick | 段階内番号（0から）／起動後のISR周期番号 |
| TxRequest_us | CANドライバへ書き込む直前の時刻 |
| RxCallback_us | 受信コールバック先頭の時刻 |
| RTT_us | 受信時刻−送信要求時刻。32 bit時刻折り返し対応 |
| Period_us | その周期と前周期のISR開始間隔 |
| ISR_us | その周期の制御ISR時間（受信コールバックの処理時間は別） |
| Status | OK / TX_FAILED / DEADLINE / CANCELLED |

- OK：次周期までに応答し、RTTがその段階の周期未満。
- TX_FAILED：CANドライバが書込みを受け付けなかった。
- DEADLINE：次周期までに応答なし、または受信RTTがその段階の周期以上。
- CANCELLED：未応答中に手動停止・安全条件で停止。
- 未受信行の受信時刻とRTTは0。実測0 µsとして扱わない。

各段階をSTAGE_BEGIN,Hz,...とSTAGE_ENDで区切り、Hz付きのTIMING_SUMMARYを出力する。
StateはCOMPLETE／ABORTED／NOT_RUN。未実行段階も明示する。
TIMING_SUMMARYには件数、状態別件数、RTTの最小・平均・最大・標準偏差、周期の最小・最大、ISR最大時間を出力。
RTT集計はOK行のみ（母標準偏差）。OKなしの場合は平均と標準偏差がnan、最小・最大が0。
周期・ISR集計は記録された行が対象。開始直後の未記録周期は含めない。
UnmatchedRxは測定中に未応答指令がない状態で届いた対象応答数。
RxQueueOverflowとHardwareOverrunsは受信欠落の診断値。

## 解釈
RTTには、こちらの送信待ち＋CAN指令伝送＋モータ側処理・応答待ち＋CAN応答伝送＋受信割り込みまでの遅延が含まれる。
Can0.write()成功は実送信完了やモータ到達確認ではない。

MIT応答には指令の通し番号がない。指令に対して応答が1件返る構成を前提とする。
自発的な周期送信、重複応答、以前の遅延応答がある場合は見かけのRTTとなる。
未応答のまま次の測定指令を送らず停止し、遅い応答を次指令に割り当てることを避ける。
UnmatchedRxが増える場合はモータ側の応答方式を確認する。

停止指令もCAN書込み失敗時には到達を保証できない。停止はブレーキ保持ではない。
